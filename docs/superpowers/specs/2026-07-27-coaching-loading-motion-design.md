# AI 코칭 답변 준비 애니메이션 설계

## 목표

AI 답변을 기다리는 동안 화면이 멈춘 것처럼 보이지 않도록, 기존 상태 영역에 명확하고 지속적인 움직임을 제공한다. 사용자는 별도의 설명 없이도 요청이 정상 처리 중임을 이해할 수 있어야 한다.

## 화면 구성

- 기존 `답변을 준비하고 있습니다` 상태 박스의 중앙 정렬과 크기는 유지한다.
- 문구 왼쪽에 작은 원형 회전 링을 배치한다.
- 문구 뒤에는 점 3개를 별도 요소로 배치하고 차례로 밝아지게 한다.
- 상태 박스 배경에는 매우 약한 좌우 빛 이동 효과를 적용한다.
- 모바일과 PC에서 한 줄을 우선 유지하되, 좁은 화면에서는 자연스럽게 줄바꿈한다.

## 동작

- AI 요청이 시작되는 즉시 링, 점, 배경 애니메이션이 함께 시작된다.
- 후속 질문 선택 후 재요청하거나 오류 화면에서 다시 시도할 때도 같은 표시를 사용한다.
- 답변, 후속 질문 또는 오류가 도착하면 로딩 영역과 애니메이션을 함께 제거한다.
- 기존 중복 제출 방지, 비활성화 버튼, 포커스 이동 로직은 변경하지 않는다.

## 접근성

- 상태 문구는 기존 `role="status"`, `aria-live="polite"`, `aria-atomic="true"`를 유지한다.
- 시각용 링과 점은 `aria-hidden="true"`로 처리해 스크린리더가 불필요하게 읽지 않도록 한다.
- 읽히는 문구는 `답변을 준비하고 있습니다.` 한 번만 제공한다.
- `prefers-reduced-motion: reduce`에서는 모든 반복 애니메이션을 중지하고 정적인 링과 점을 표시한다.

## 구현 범위

- `src/ui/coaching.ts`: 로딩 상태일 때만 시각용 링과 점 마크업을 생성한다.
- `src/styles.css`: 회전, 점 순차 강조, 약한 배경 이동, 반응형 및 모션 감소 규칙을 추가한다.
- 기존 서버 요청, OpenAI 호출, Supabase 저장 흐름은 변경하지 않는다.

## 검증 기준

- 로딩 중에만 링과 점 요소가 존재한다.
- 링과 점은 보조기술에서 숨겨진다.
- CSS에 세 종류의 움직임과 모션 감소 대체 규칙이 존재한다.
- 요청 완료 후 로딩 시각 요소가 사라진다.
- 기존 코칭 UI 테스트와 전체 회귀 테스트가 통과한다.
