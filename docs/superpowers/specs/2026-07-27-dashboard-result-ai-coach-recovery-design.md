# 대시보드 결과 재진입 및 AI 코치 복구 설계

## 목표

사용자가 대시보드에서 최근 진단의 전체 결과를 다시 확인하고, 매출·광고·재방문·플레이스 관련 질문을 AI 코치에게 바로 입력할 수 있게 한다. 현재 운영 환경에서 모든 코칭 요청을 막고 있는 Vercel 서버 함수 모듈 오류를 해결한다.

## 확인된 현재 문제

- 대시보드는 최근 진단의 목표 매출과 최대 필요 고객 수만 요약하며 전체 결과 화면으로 이동하는 기능이 없다.
- AI 자유 질문 입력은 코칭 화면 아래에 있어 주요 기능으로 인식하기 어렵다.
- 2026년 7월 27일 최근 1시간 운영 로그에서 `/api/coaching` 요청 4건이 모두 HTTP 500으로 실패했다.
- 실패 원인은 OpenAI 호출이나 API 키가 아니라 Vercel 함수 시작 단계의 `ERR_MODULE_NOT_FOUND`이다.
- 배포된 ESM 파일 `api/coaching.js`가 확장자 없는 로컬 경로 `api/_lib/coaching-handler`를 불러오면서 Node.js가 모듈을 찾지 못한다.

## 선택한 접근

현재 Vite·Vercel·Supabase 구조는 유지한다.

- Vercel 서버 함수가 사용하는 로컬 import를 Node ESM 호환 경로로 수정한다.
- 별도 번들러 추가나 Supabase Edge Function 이전은 하지 않는다.
- 실제 Vercel과 유사하게 서버 TypeScript를 JavaScript로 출력한 뒤 Node.js가 진입 모듈을 불러올 수 있는지 자동 검사한다.

## 대시보드

### 최근 진단 결과

- 완료된 최근 진단이 있으면 `최근 진단 결과 전체 보기` 버튼을 최근 진단 요약 안에 표시한다.
- 버튼을 누르면 저장된 최신 진단을 기반으로 기존 결과 화면을 읽기 전용으로 표시한다.
- 다음 항목을 새 진단 직후와 동일하게 보여준다.
  - 목표까지 부족한 매출
  - 최대 필요 신규 고객 수
  - 월 영업일 기준 하루 최대 추가 고객 수
  - 계산 기준
  - 매장 운영 정보가 있는 경우 운영 분석
  - 추천 행동과 판단 근거
- 읽기 전용 결과에서는 `7일 행동으로 저장하기`를 표시하지 않아 같은 행동이 중복 저장되지 않게 한다.
- 결과 상단에 `대시보드로 돌아가기`를 제공한다.
- 저장 데이터가 완료 조건을 충족하지 못하면 전체 보기 버튼을 표시하지 않고 기존 요약만 유지한다.

### AI 바로 질문

- 현재 행동 카드 다음, 지난 결과 기록 이전에 `AI 코치에게 바로 질문하기` 카드를 배치한다.
- 설명 문구는 AI가 최신 진단을 바탕으로 질문을 해석하고 지금 할 행동을 제안한다는 점을 밝힌다.
- 질문 입력은 500자 이내이며 빈 질문은 전송하지 않는다.
- 다음 예시를 선택 가능한 질문으로 제공한다.
  - `광고를 하는데 손님이 늘지 않아요`
  - `재방문 고객을 어떻게 확인하나요?`
  - `객단가를 올리려면 무엇부터 해야 하나요?`
- 입력하거나 예시를 선택해 전송하면 최신 진단 ID와 질문을 코칭 화면으로 전달하고 자동으로 첫 요청을 시작한다.
- 완료된 최근 진단이 없으면 AI 질문 카드를 표시하지 않는다.

## AI 코칭 화면

- 자유 질문 카드를 고민 유형 선택보다 먼저 표시한다.
- 제목은 `AI 코치에게 직접 물어보세요`로 표시한다.
- 도움말은 `매출·광고·재방문·플레이스 고민을 최신 진단을 바탕으로 답해드려요.`로 표시한다.
- 고민 유형 선택은 `또는 고민 유형으로 시작하기`라는 보조 영역으로 유지한다.
- 대시보드에서 전달된 초기 질문이 있으면 화면 진입과 동시에 한 번만 전송한다.
- 사용자가 직접 입력한 질문과 대시보드에서 전달된 질문은 같은 검증·요청·응답 경로를 사용한다.

## 최근 결과 데이터 변환

- 저장된 `AssessmentSnapshot`을 `ResultViewModel`로 변환하는 순수 함수를 둔다.
- 기존 완료 진단 검증을 통과한 데이터만 변환한다.
- 저장된 입력과 계산 결과를 사용해 광고·매장 운영·병목·추천 행동을 복원한다.
- 추천 행동은 저장된 진단과 현재 도메인 규칙의 일관성을 확인한 뒤 표시한다.
- 잘못되거나 불완전한 저장 데이터는 예외 대신 `null`을 반환해 대시보드가 계속 표시되게 한다.

## AI 서버 함수 복구

- `api/coaching.ts`에서 시작해 런타임에 도달하는 모든 로컬 import에 출력 JavaScript 기준의 `.js` 확장자를 사용한다.
- API 전용 파일뿐 아니라 API가 불러오는 `src/coaching` 및 해당 도메인 모듈의 런타임 import도 동일한 규칙으로 정리한다.
- 타입 전용 import도 TypeScript와 출력 모듈 해석이 일관되도록 같은 경로 규칙을 사용한다.
- `package.json`의 ESM 설정을 제거하거나 애플리케이션 전체를 CommonJS로 변경하지 않는다.
- OpenAI 키와 Supabase 서버 키는 계속 Vercel 서버 환경변수에서만 읽는다.

## 오류 처리와 관측성

- 클라이언트는 실패한 질문과 마지막 요청을 유지해 `다시 시도하기`가 동일 요청을 보낸다.
- 서버는 외부 응답 본문, 사용자 질문 전문, 인증 토큰, 환경변수 값을 로그에 남기지 않는다.
- 최상위 요청 실패 시 안전한 내부 오류 코드와 오류 종류만 서버 로그에 남긴다.
- 클라이언트에는 기존과 같이 비기술적인 재시도 안내를 제공한다.
- OpenAI 분류 또는 문장 선택이 실패해도 기존 규칙 기반 코칭 답변을 사용할 수 있는 현재 폴백을 유지한다.

## 접근성 및 반응형

- 최근 결과와 AI 질문 진입은 모두 실제 `button` 또는 `form` 요소로 제공한다.
- 자동 전송 중에는 중복 요청을 막고 로딩 상태를 스크린 리더에 알린다.
- 모바일에서는 AI 질문 카드의 입력창, 예시 버튼, 전송 버튼을 한 열로 배치한다.
- 제목은 단어 단위 줄바꿈 규칙을 유지하고 긴 사용자 입력만 안전하게 줄바꿈한다.
- 결과 화면의 대시보드 복귀 버튼은 키보드로 접근할 수 있고 명확한 레이블을 갖는다.

## 테스트

### 단위 및 UI 테스트

- 완료된 진단에 전체 결과 보기 버튼이 나타나는지 확인한다.
- 불완전한 진단에는 전체 결과 보기와 AI 질문 카드가 나타나지 않는지 확인한다.
- 저장 진단이 결과 모델로 정확히 변환되는지 확인한다.
- 읽기 전용 결과에 행동 저장 버튼이 없고 대시보드 복귀가 동작하는지 확인한다.
- 대시보드 자유 질문의 빈 값·500자 제한·예시 선택·자동 전송을 확인한다.
- 코칭 화면에서 자유 질문 영역이 고민 유형보다 먼저 표시되는지 확인한다.
- 초기 질문은 한 번만 전송되고 실패 후 동일 질문으로 재시도되는지 확인한다.

### 서버 함수 테스트

- 서버 함수 진입점과 모든 런타임 의존성을 JavaScript로 출력한다.
- 출력된 `api/coaching.js`를 Node ESM으로 import해 모듈 해석이 성공하는지 확인한다.
- API 인증, 속도 제한, 폴백, OpenAI 응답 검증 관련 기존 테스트를 유지한다.
- 안전한 오류 로그에 질문·토큰·키가 포함되지 않는지 확인한다.

### 전체 및 운영 검증

- 형식 검사, 타입 검사, 전체 Vitest, 보안 검사, Vite 프로덕션 빌드를 실행한다.
- GitHub 통합 후 Vercel Production 배포가 `Ready`인지 확인한다.
- 실제 계정으로 최근 결과 전체 보기와 대시보드 복귀를 확인한다.
- 대시보드에서 질문을 전송해 `/api/coaching`이 HTTP 200 또는 정상 후속 질문 응답을 반환하는지 확인한다.
- 배포 직후 Vercel 런타임 로그에서 새 모듈 오류와 500 응답이 없는지 확인한다.
