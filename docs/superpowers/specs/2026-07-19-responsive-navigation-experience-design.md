# 장사네비게이션 반응형 고객 경험 개편 디자인

## 목적

기존 구매자 인증, 매장 진단, 결과 저장, 실행 계획 확인 기능은 유지하면서 서비스 이름을 `장사네비게이션`으로 통일한다. 첫 방문자는 서비스의 가치를 이해한 뒤 진단을 시작하고, 가입 이후의 작업 화면에서는 매출 수치와 다음 행동을 빠르게 읽을 수 있어야 한다. PC와 모바일 모두에서 같은 정보 우선순위를 유지하되 화면 크기에 맞는 배치를 사용한다.

## 디자인 방향

선택한 방향은 여정 중심 혼합형이다.

- 첫 화면은 짙은 네이비와 차콜 기반의 프리미엄 브랜드 영역으로 만든다.
- 가입, 진단, 결과, 대시보드는 밝은 배경과 높은 명도 대비를 사용한다.
- 강조색은 진행과 성장을 나타내는 초록, 주의와 보조 강조를 위한 따뜻한 주황으로 제한한다.
- 업로드한 Xero 예시에서는 중앙 집중형 히어로, 유연한 크기 조절, 모바일 메뉴와 터치 영역, 단계 흐름 표현만 참고한다. 보라·분홍색 브랜드와 복잡한 빔 애니메이션은 복제하지 않는다.
- 장식보다 제목, 숫자, 현재 단계, 다음 행동의 시각적 우선순위를 높인다.

## 전체 사용자 여정

### 1. 브랜드 소개

비로그인 사용자는 운영 환경에서도 곧바로 긴 가입 폼을 보지 않는다. 먼저 다음 내용을 한 화면에서 확인한다.

- 제품명: 장사네비게이션
- 핵심 문구: 목표 매출까지, 필요한 고객 수와 오늘 할 일을 찾습니다
- 짧은 설명: 가게 수치를 바탕으로 필요한 고객 수와 우선 행동을 안내한다
- 기본 행동: `내 가게 진단 시작하기`
- 보조 행동: `기존 사용자 로그인`
- 신뢰 정보: 약 3분, 카드정보 불필요, 입력 정보 사용 목적
- 과정 미리보기: 목표 매출 설정 → 필요한 고객 수 확인 → 오늘의 행동 선택

데모 환경에서는 기본 행동이 곧바로 샘플 진단을 연다. 운영 환경에서는 기본 행동이 신규 가입 패널을 열고, 보조 행동은 로그인 패널을 연다.

### 2. 가입과 로그인

가입과 로그인은 같은 밝은 인증 화면에서 탭 또는 명확한 전환 버튼으로 구분한다. 신규 가입을 기본 상태로 보여주되 기존 사용자는 한 번의 선택으로 로그인 폼에 접근한다.

- PC: 왼쪽에는 가입 이유와 입력 정보 안내, 오른쪽에는 폼을 배치한다.
- 모바일: 안내를 짧게 줄이고 폼 위에 배치한다.
- 필수·선택 항목을 라벨에서 즉시 구분한다.
- 오류는 해당 입력 바로 아래에 표시하고 첫 오류 입력으로 초점을 이동한다.
- 이메일 전송 중에는 버튼을 잠그고 현재 상태를 문장으로 보여준다.
- 인증 링크에서 돌아온 경우에는 별도 확인 화면에서 사용자가 명시적으로 가입 완료 버튼을 누르는 기존 보안 흐름을 유지한다.

### 3. 진단

기존 3단계 계산 구조는 유지하되 각 단계에서 사용자가 지금 무엇을 입력하는지 명확히 보여준다.

- 상단에 `1 / 3` 형태의 현재 단계와 진행 막대를 고정적으로 보여준다.
- 단계 제목 아래에는 왜 이 정보가 필요한지 한 문장으로 설명한다.
- PC에서는 관련 숫자 입력을 2열로 배치하되 한 질문의 선택지는 한 덩어리로 유지한다.
- 모바일에서는 모든 질문을 한 열로 쌓고, 하단 행동 버튼을 화면 폭에 맞게 크게 제공한다.
- 숫자 입력에는 원·명·일·% 단위를 입력 칸 바깥에 표시하고 예시 값을 제공한다.
- 재방문 고객 수를 모르는 사용자는 `잘 모르겠어요`를 명확한 정상 선택지로 제공하고 신규 고객 기준의 보수적 계산 설명을 보여준다.
- 선택형 항목은 작은 라디오 버튼 대신 전체 카드를 누를 수 있게 한다.

### 4. 결과

결과 화면은 계산값을 나열하지 않고 의사결정 순서로 보여준다.

1. 목표 매출과 현재 매출의 차이
2. 필요한 월간·일간 고객 수
3. 계산에 사용한 가정과 데이터 상태
4. 현재 병목에 대한 쉬운 설명
5. 오늘 실행할 행동 한 가지

가장 중요한 고객 수는 큰 숫자 카드로 표시한다. 추정치에는 `추정` 배지를 붙이고, 펼쳐보는 설명에서 계산 기준을 확인할 수 있게 한다. 행동 카드에는 예상 시간, 실행 단계, 확인할 지표, 피해야 할 행동을 구분한다. `7일 행동으로 저장하기`를 대표 버튼으로 둔다.

### 5. 대시보드

대시보드는 매장 현황, 현재 행동, 다가오는 확인, 완료 기록 순서로 구성한다.

- 상단에 업체명과 목표 매출을 표시한다.
- 현재 행동 카드를 가장 먼저 보여주고 확인 예정일과 측정 지표를 강조한다.
- 완료 기록은 실행 전·후 변화가 한눈에 비교되도록 두 열 또는 화살표 구조를 사용한다.
- 새 진단 시작 버튼은 현재 행동보다 시각적으로 강하지 않은 보조 버튼으로 둔다.
- 데이터가 없거나 불러오지 못한 경우에도 사용자가 할 수 있는 다음 행동과 로그아웃을 유지한다.

## 화면 구조와 컴포넌트 경계

현재 TypeScript 렌더링 구조와 서비스 인터페이스는 유지한다. React 전환은 이번 범위에 포함하지 않는다.

- `shell`: 브랜드 소개, 소개 내비게이션, 운영/데모 진입 분기
- `onboarding`: 신규 가입과 기존 사용자 로그인 표시 상태, 인증 확인
- `diagnosis`: 진행 표시, 단계별 질문 그룹, 이전/다음 행동
- `result`: 핵심 숫자 요약, 가정 설명, 권장 행동
- `dashboard`: 매장 요약, 현재 행동, 확인 기록
- `styles`: 브랜드 토큰, 공통 레이아웃, 폼·카드·버튼, 반응형 규칙

서비스 호출, 계산 함수, Supabase 인증·저장 계약은 변경하지 않는다. 화면 모듈은 기존 콜백과 데이터 속성을 유지해 테스트와 서버 경계를 보존한다.

## 반응형 규칙

- 최대 콘텐츠 폭은 소개 화면 1200px, 작업 화면 960px로 제한한다.
- 1024px 이상에서는 설명과 입력, 요약과 행동을 필요에 따라 2열로 배치한다.
- 720px 이하에서는 모든 주요 영역을 한 열로 전환하고 좌우 여백을 16px로 줄인다.
- 모바일 버튼과 입력은 최소 48px 높이로 만들고 주요 버튼은 전체 폭을 사용한다.
- 작은 화면에서 표 형태 데이터는 카드 또는 세로 비교로 바꿔 가로 스크롤을 만들지 않는다.
- 긴 업체명, 큰 통화 값, 확대 글꼴에서도 콘텐츠가 잘리거나 겹치지 않게 줄바꿈을 허용한다.
- 동작 애니메이션은 200ms 안팎의 화면 전환과 진행 변화에만 사용하며 `prefers-reduced-motion`을 존중한다.

## 접근성과 가독성

- 본문은 최소 16px, 보조 문구는 최소 14px를 유지한다.
- 텍스트와 배경은 WCAG AA 수준의 대비를 목표로 한다.
- 색상만으로 상태를 구분하지 않고 텍스트·아이콘·테두리를 함께 사용한다.
- 키보드 초점은 모든 링크, 버튼, 입력, 선택 카드에서 분명히 보이게 한다.
- 기존 `role=status`, `aria-live`, 오류 연결과 초점 이동 동작을 유지한다.
- 모바일 메뉴를 추가할 경우 열림 상태, 닫기 버튼, 본문 스크롤 잠금, Escape 닫기를 제공한다. 현재 첫 버전에서는 항목이 적으므로 전체 화면 메뉴 대신 간결한 상단 행동을 우선한다.

## 오류와 로딩 상태

- 네트워크 처리 중에는 해당 버튼만 비활성화하고 입력 내용은 보존한다.
- 오류 문구는 기술 용어 없이 사용자가 다음에 할 일을 포함한다.
- 로그인 여부 확인 중에는 브랜드가 유지되는 짧은 로딩 상태를 보여 화면 깜빡임을 줄인다.
- 데이터 저장 실패 시 현재 진단이나 체크인 폼을 그대로 유지한다.
- 결과가 추정치이거나 데이터가 부족하면 실패처럼 보이지 않도록 가정과 보완 방법을 함께 안내한다.

## 검증 기준

- 제품명이 모든 핵심 화면에서 `장사네비게이션`으로 표시된다.
- 운영 환경 비로그인 사용자는 소개 화면에서 신규 가입 또는 기존 로그인으로 이동할 수 있다.
- 데모 환경 사용자는 소개 화면에서 샘플 진단을 시작할 수 있다.
- 375px, 768px, 1440px 폭에서 가로 넘침 없이 핵심 행동이 보인다.
- 모바일의 입력과 버튼은 손가락으로 누르기 충분한 크기다.
- 진단의 3단계 진행 상태와 현재 단계가 명확하다.
- 결과 화면에서 필요한 고객 수와 오늘의 행동을 스크롤 초반에 확인할 수 있다.
- 인증 완료는 기존처럼 명시적 사용자 동작으로만 실행된다.
- 실패 시 작성한 값과 재시도 수단이 유지된다.
- 기존 계산, 서비스, 데이터베이스 보안 테스트를 포함한 전체 검증이 통과한다.

- 새로운 개인정보 수집 항목
