# 집중형 진단 위저드 디자인

## 목표

장사네비게이션 진단 화면을 긴 설문 문서가 아니라, 사용자가 한 챕터씩 집중해 완료하는 3단계 반응형 위저드로 바꾼다. 기존 입력 항목, 계산, 검증, 저장 방식은 유지한다.

## 현재 문제

- 모든 `step-panel`이 동시에 표시되어 화면이 지나치게 길다.
- 현재 진행 중인 챕터와 다음 행동의 구분이 약하다.
- 모바일에서 질문과 버튼이 한 화면에 과도하게 이어져 피로도가 높다.
- 한글 문장이 컨테이너 끝에서 어색하게 끊기는 경우가 있다.

## 선택한 방향

현재 챕터만 보여주는 집중형 단계 카드 방식을 사용한다.

- 1단계: 매출 목표
- 2단계: 현재 고객 상황
- 3단계: 실행 조건

각 단계는 하나의 독립된 화면처럼 보이지만 동일한 폼 안에서 동작한다. 이전·다음 이동 시 입력값은 유지하며, 현재 단계가 유효할 때만 다음 단계로 넘어간다.

## 화면 구조

### 공통

- 상단 작업 헤더에 현재 단계, 챕터 이름, 전체 진행률을 표시한다.
- 본문에는 현재 단계의 제목, 짧은 설명, 질문만 표시한다.
- 하단 행동 영역에는 이전·다음 또는 결과 보기 버튼을 배치한다.
- 선택형 답변은 충분한 터치 영역을 가진 카드 형태를 유지한다.
- 선택 입력과 비교 수치는 접을 수 있는 보조 영역으로 남긴다.

### 모바일

- 한 열 레이아웃을 사용한다.
- 화면 좌우 여백을 줄이고 입력·선택·버튼을 전체 너비로 표시한다.
- 진행 정보는 짧게 유지하며 행동 버튼이 질문과 명확히 분리되도록 한다.
- 최소 44px 이상의 조작 영역을 제공한다.

### PC

- 질문을 읽기 좋은 중앙 폭으로 제한한다.
- 카드 내부 여백과 질문 간격을 넉넉하게 사용한다.
- 숫자 입력은 의미가 연결된 항목끼리 2열로 배치하되, 선택 질문은 읽기 편한 폭을 유지한다.

## 단계 전환

- 비활성 단계에는 `hidden`을 적용하고 스타일에서도 강제로 노출되지 않도록 보장한다.
- 단계가 바뀌면 진행률, 단계 번호, 챕터 이름을 함께 갱신한다.
- 새 단계의 제목으로 초점을 이동해 화면 읽기 도구와 키보드 사용자가 현재 위치를 알 수 있게 한다.
- 짧은 페이드·상승 전환을 사용하며 `prefers-reduced-motion` 환경에서는 애니메이션을 제거한다.
- 이전 단계로 돌아가도 입력값과 선택값을 그대로 유지한다.

## 문장 가독성

- 설명과 선택지에는 한글 어절 중심 줄바꿈을 적용한다.
- 버튼 문구와 짧은 라벨은 불필요하게 두 줄로 갈라지지 않도록 한다.
- 긴 내용은 임의로 작게 축소하지 않고 컨테이너 안에서 자연스럽게 줄바꿈한다.

## 오류 처리

- 현재 단계의 필수값이 없거나 잘못되면 단계 이동을 막는다.
- 첫 번째 오류 항목으로 초점을 옮기고 해당 항목 가까이에 오류 문구를 표시한다.
- 숨겨진 단계의 오류나 입력값을 임의로 초기화하지 않는다.
- 저장 실패와 제출 중 상태에 관한 기존 동작은 유지한다.

## 테스트

- 최초 진입 시 1단계만 보이는지 확인한다.
- 유효한 입력 후 다음 단계로 이동하면 이전 단계는 숨고 새 단계만 보이는지 확인한다.
- 이전으로 돌아갔을 때 입력값이 유지되는지 확인한다.
- 진행률과 챕터명이 단계에 맞게 갱신되는지 확인한다.
- 모바일 반응형 규칙, 한글 줄바꿈, 동작 영역 크기에 대한 스타일 계약을 확인한다.
- 기존 진단 계산·검증·저장 테스트 전체를 실행해 회귀가 없는지 확인한다.

## 범위 제외

- 질문 항목과 진단 계산 방식 변경
- 데이터베이스 구조 변경
- 로그인 및 초대 코드 흐름 변경
- 새로운 챕터 추가
