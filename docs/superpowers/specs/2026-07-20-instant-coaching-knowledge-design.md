# 장사네비게이션 즉문즉답 코치 설계

## 1. 목적

기존 진단을 완료한 소상공인 대표가 현재 고민을 선택하거나 직접 질문하면, 장사네비게이션이 저장된 매출·객단가·영업일·고객 수·매장 수용 여력을 근거로 지금 실행할 행동 한 가지를 제안한다.

이 기능의 목표는 범용 AI 상담이 아니다. 질문의 표현은 AI가 이해하되, 판단과 행동 추천은 장사네비게이션의 계산식, 명시적인 분기 규칙, 검토된 코칭 콘텐츠가 담당한다. 사용자는 긴 보고서 대신 자신의 상황을 반영한 짧고 실행 가능한 답변을 받는다.

## 2. 제품 원칙

- 기본 진단을 완료한 사용자만 즉문즉답 코치를 사용할 수 있다.
- 한 번의 답변에서는 행동 한 가지만 추천한다.
- AI는 질문을 분류하고 설명을 자연스럽게 만드는 역할만 맡는다.
- 계산, 행동 선택, 금지 조건은 결정론적인 애플리케이션 규칙이 담당한다.
- 근거가 부족하면 추정하지 않고 먼저 측정할 행동을 추천한다.
- 다른 전자책은 내부 참고자료로만 사용한다. 문장, 표, 고유한 구성은 사용자 화면에 복제하지 않는다.
- 매출 상승, 광고 성과, 검색 순위를 보장하지 않는다.
- 허위 리뷰, 인위적 트래픽, 저장 수 구매 등 플랫폼 조작을 안내하지 않는다.

## 3. 사용자 진입 조건과 흐름

### 3.1 진입 조건

최근 완료한 진단 결과가 있는 로그인 사용자에게 대시보드의 `지금 고민 해결하기` 버튼을 제공한다. 진단 결과가 없으면 기존 진단 시작 화면으로 안내하며, 일반적인 AI 답변을 대신 제공하지 않는다.

### 3.2 첫 화면

다음 여섯 개의 고민 카드를 표시한다.

1. 검색해도 우리 가게가 잘 안 보여요.
2. 플레이스는 보는데 방문하지 않아요.
3. 광고비는 쓰는데 손님이 늘지 않아요.
4. 손님은 오는데 객단가가 낮아요.
5. 한 번 온 고객이 다시 오지 않아요.
6. 무엇이 문제인지 모르겠어요.

카드 아래에는 `직접 질문하기` 입력창을 둔다. 카드와 직접 질문은 같은 코칭 처리 흐름을 사용한다.

### 3.3 대화 흐름

1. 사용자가 고민 카드 또는 직접 질문을 제출한다.
2. AI 분류기가 질문을 진단 영역과 고민 유형으로 분류한다.
3. 행동 선택에 꼭 필요한 값이 없을 때만 추가 질문을 제시한다.
4. 추가 질문은 한 화면에 하나씩, 한 세션에서 최대 두 개까지만 묻는다.
5. 규칙 엔진이 승인된 행동 목록에서 한 가지를 선택한다.
6. 답변 작성기가 선택된 근거와 행동을 짧은 코칭 카드로 구성한다.
7. 사용자는 답변을 평가하거나 다른 고민을 이어서 물을 수 있다.

### 3.4 답변 구조

모든 답변은 다음 순서를 유지한다.

1. 현재 상황 한 줄 요약
2. 가장 가능성이 높은 문제 단계
3. 그렇게 판단한 근거
4. 지금 바로 할 행동 한 가지
5. 실행 방법 2~3단계
6. 확인해야 할 숫자
7. 지금 하지 말아야 할 것
8. 다른 고민 이어서 묻기

모바일에서는 각 항목을 별도 카드 또는 명확한 소제목으로 구분한다. 기본 답변은 한 화면에서 핵심을 파악할 수 있는 길이로 제한하고, 상세 근거는 사용자가 펼쳐 볼 수 있게 한다.

## 4. 진단 영역

질문과 추가 답변은 다음 여섯 영역 중 하나를 주 영역으로 갖는다.

| 영역   | 의미                                                     | 대표 신호                                |
| ------ | -------------------------------------------------------- | ---------------------------------------- |
| 발견   | 검색 결과에서 가게를 찾기 어렵다                         | 검색어, 노출, 지역·업종 정보             |
| 선택   | 노출은 되지만 가게의 매력이 전달되지 않는다              | 대표사진, 메뉴, 가격, 선택 이유          |
| 확신   | 방문 전 걱정과 질문이 해결되지 않는다                    | 영업시간, 주차, 예약, 웨이팅, 리뷰       |
| 방문   | 관심이나 클릭이 실제 방문으로 이어지지 않는다            | 전화, 예약, 길찾기, 광고 유입, 실제 방문 |
| 재방문 | 첫 방문 뒤 다시 올 이유나 연결 수단이 약하다             | 만족도, 방문 이력, 동의 고객 목록        |
| 수익   | 고객은 있으나 객단가·수용 여력·운영 구조가 매출을 막는다 | 객단가, 좌석, 혼잡 시간, 포장·배달       |

분류 결과가 불명확하면 `무엇이 문제인지 모르겠어요` 흐름을 사용한다. 이 흐름에서는 진단 수치와 최대 두 개의 확인 질문으로 우선 확인할 영역을 정하고, 여전히 근거가 부족하면 측정 행동을 추천한다.

## 5. 초기 코칭 행동 15개

### 5.1 발견

1. 우리 가게가 실제로 노출되는 검색어 확인
2. 큰 키워드 대신 방문 목적이 분명한 세부 검색어 후보 작성

### 5.2 선택

3. 대표사진이 무엇을 파는 가게인지 바로 보여주는지 점검
4. 대표 메뉴의 가격·추천 인원·주문 조합 정리
5. 매장을 선택할 한 가지 이유 정의

### 5.3 확신

6. 영업시간·주차·예약·웨이팅·단체 이용 정보 점검
7. 리뷰에서 반복되는 고객 질문과 불만 분류
8. 상세설명을 고객 질문에 대한 답변으로 수정

### 5.4 방문

9. 광고 고객의 실제 방문 경로 기록
10. 클릭·전화·예약·방문 중 이탈 지점 확인

### 5.5 재방문

11. 첫 방문 경험에서 다시 올 이유 점검
12. 적법하게 동의받은 고객에게 재방문 이유 안내

### 5.6 수익

13. 대표 메뉴 옆에 자연스러운 추가 주문 한 가지 제안
14. 붐비는 시간과 한산한 시간을 분리해 운영
15. 좌석이 찬 상태에서 광고보다 회전·포장·배달 구조 점검

각 행동은 추천 조건뿐 아니라 추천 금지 조건을 가져야 한다. 예를 들어 고객 수용 여력이 없는 매장에는 신규 고객 광고 확대를 추천하지 않는다. 고객 연락 동의가 확인되지 않은 경우에는 재방문 메시지 발송을 추천하지 않는다.

## 6. 지식 관리와 출처 정책

### 6.1 지식 등급

모든 코칭 지식은 다음 등급 중 하나를 갖는다.

- `official`: 현재 공식 문서로 확인된 기능과 정책
- `principle`: 플랫폼이 바뀌어도 유지되는 고객 경험·매출 원칙
- `hypothesis`: 매장별 소규모 검증이 필요한 실전 가설
- `prohibited`: 허위 리뷰, 인위적 트래픽, 순위 조작 등 사용 금지 지식

`official`, `principle`, `hypothesis`만 행동 콘텐츠에 연결할 수 있다. `hypothesis`를 사용하는 답변에는 결과를 보장하지 않으며 작게 시험하고 확인할 숫자를 함께 제시한다. `prohibited`는 추천 후보에 들어가지 않으며, 관련 질문에는 거절과 정상적인 대안을 제공한다.

### 6.2 외부 참고자료

제공받은 외부 전자책은 내부 편집 자료로만 사용한다. 원문 검색 결과를 사용자에게 직접 보여주는 RAG 방식은 사용하지 않는다. 유용한 원리는 장사네비게이션의 자체 판단 체계와 문장으로 다시 작성한다.

다음 내용은 채택한다.

- 고객 경로별 이탈 진단
- 업체 정보·사진·메뉴·가격·예약·주차 정보의 완성도
- 광고 노출·클릭과 실제 전화·예약·방문의 구분
- 신규 고객·재방문·객단가의 분리
- 검색 의도와 방문 목적이 분명한 설명
- 측정 가능한 숫자를 기준으로 작은 행동을 반복하는 원칙

다음 내용은 제외한다.

- 허위 영수증 리뷰와 리뷰 구매
- 저장 수, 트래픽, 기타 반응 구매
- 고객에게 특정 리뷰 문구나 키워드를 강요하는 방법
- 근거가 공개되지 않은 순위 공식과 순위 보장
- 고정된 페이지 순위·체류시간 등 절대 기준
- 모든 플랫폼 기능 사용이 순위를 높인다는 단정
- 현재 제공 여부를 확인하지 않은 오래된 기능별 설정법

### 6.3 공식 자료 검토

플랫폼 관련 `official` 지식은 공식 스마트플레이스 또는 네이버 검색광고 자료를 근거로 하고 `verifiedAt`과 `reviewAfter`를 기록한다. 검토 기한이 지난 지식은 자동 추천에서 제외하고 일반 원칙 또는 측정 행동으로 대체한다.

## 7. 시스템 구성

### 7.1 질문 분류기

AI 질문 분류기는 자유 질문을 구조화된 결과로 변환한다.

```ts
type CoachingIntent =
  | "discovery"
  | "selection"
  | "confidence"
  | "visit"
  | "returning"
  | "profit"
  | "unknown";

interface IntentResult {
  intent: CoachingIntent;
  confidence: number;
  signals: string[];
  requestedOutcome?: string;
}
```

분류기는 행동을 직접 선택하지 않는다. 신뢰도가 기준보다 낮으면 `unknown`으로 처리한다. 사용자가 입력한 자유 질문은 명령문으로 신뢰하지 않고 분류 대상 텍스트로만 다룬다.

### 7.2 코칭 컨텍스트

규칙 엔진에는 다음 정보만 전달한다.

- 최근 완료한 진단 수치와 수치의 정확도 상태
- 매장 수용 여력과 선택 운영 정보
- 분류된 고민 영역
- 현재 세션의 추가 답변
- 과거에 완료한 코칭 행동 키

이름, 이메일, 연락처, 초대 코드, 원문 전자책은 AI 입력에 포함하지 않는다. 업체명도 답변 생성에 필수적이지 않으므로 기본적으로 제외한다.

### 7.3 행동 콘텐츠 모델

```ts
interface CoachingActionDefinition {
  key: string;
  intent: CoachingIntent;
  title: string;
  triggerKeys: string[];
  blockerKeys: string[];
  requiredEvidence: string[];
  followUpQuestions: string[];
  reasonTemplate: string;
  steps: string[];
  metric: string;
  avoid: string;
  evidenceLevel: "official" | "principle" | "hypothesis";
  verifiedAt: string;
  reviewAfter?: string;
  version: number;
}
```

초기 콘텐츠는 코드로 버전 관리한다. 행동 수와 편집 빈도가 커지면 같은 인터페이스를 유지한 채 관리용 데이터 저장소로 이전할 수 있다.

### 7.4 규칙 엔진

규칙 엔진은 다음 순서로 행동을 선택한다.

1. 플랫폼 조작 또는 금지 요청인지 검사한다.
2. 목표 매출 달성 여부와 매장 수용 여력을 확인한다.
3. 필수 근거가 없는 경우 최대 두 개의 후속 질문을 선택한다.
4. 여전히 근거가 없으면 측정 행동을 선택한다.
5. 차단 조건을 만족하는 행동을 제거한다.
6. 고민 영역, 진단 데이터, 사용자가 원하는 결과와 가장 잘 맞는 행동 한 가지를 선택한다.
7. 같은 행동이 반복되지 않도록 최근 완료 행동을 보조 기준으로 사용한다. 단, 여전히 필요한 행동이면 반복을 허용한다.

규칙 엔진의 같은 입력은 항상 같은 결과를 반환해야 한다.

### 7.5 답변 작성기

답변 작성기는 선택된 행동, 사용 가능한 근거, 표시 가능한 진단 수치를 입력받아 정해진 답변 스키마를 반환한다. 새로운 계산, 행동 또는 플랫폼 사실을 만들 수 없다.

```ts
interface CoachingResponse {
  situation: string;
  stage: string;
  evidence: string[];
  actionTitle: string;
  steps: string[];
  metric: string;
  avoid: string;
  disclaimer?: string;
}
```

스키마 검증에 실패하거나 허용되지 않은 수치·행동이 포함되면 AI 응답을 폐기하고 템플릿 기반 기본 답변을 표시한다.

### 7.6 서버 경계와 AI 공급자

브라우저에서 AI 공급자를 직접 호출하지 않는다. 클라이언트는 Vercel 서버 함수의 코칭 API만 호출하고, 서버 함수가 다음 작업을 수행한다.

1. Supabase 로그인 토큰을 검증한다.
2. 요청한 진단 결과가 현재 사용자 소유인지 확인한다.
3. 개인정보를 제거한 코칭 컨텍스트를 구성한다.
4. 질문 분류기와 답변 작성기 어댑터를 호출한다.
5. 구조화된 응답을 검증한 뒤 세션과 추천 기록을 저장한다.

AI 공급자 키는 Vercel 서버 환경 변수에만 보관한다. 공급자별 호출 코드는 공통 인터페이스 뒤에 격리해 모델이나 공급자를 변경해도 규칙 엔진과 코칭 콘텐츠가 바뀌지 않게 한다. 첫 구현은 구조화된 JSON 응답과 서버 측 비밀키 사용을 지원하는 공급자 한 곳만 연결한다. 공급자 장애 시에는 규칙 엔진이 선택한 템플릿 답변으로 즉시 대체한다.

비용과 남용을 통제하기 위해 로그인 사용자별 요청 빈도 제한, 질문 길이 제한, 세션당 후속 질문 제한을 서버에서 적용한다. 클라이언트가 전달한 진단 수치나 행동 키를 신뢰하지 않고 서버가 저장된 진단 결과와 승인된 콘텐츠를 다시 조회한다.

## 8. 데이터 저장

코칭 개선과 사용자의 이어 묻기를 위해 다음 정보를 저장한다.

### `coaching_sessions`

- 사용자 및 기준 진단 ID
- 최초 고민 카드 키 또는 자유 질문
- 분류된 고민 영역과 분류 신뢰도
- 세션 상태와 생성·완료 시각
- 사용한 진단 스냅샷 버전

### `coaching_messages`

- 세션 ID
- 발화 주체
- 사용자 질문 또는 구조화된 답변
- 메시지 순서와 생성 시각

### `coaching_recommendations`

- 세션 ID
- 선택된 행동 키와 콘텐츠 버전
- 판단에 사용한 근거 키
- 선택 당시의 핵심 수치 스냅샷
- 사용자 평가

자유 질문 원문은 제품 개선 목적에 필요한 기간만 보관할 수 있게 별도 보존 정책을 둔다. 분석용 데이터에서는 이메일과 업체 연락처를 포함하지 않는다.

세 테이블에는 사용자별 행 수준 보안을 적용한다. 사용자는 자신이 소유한 진단에 연결된 코칭 기록만 조회·생성할 수 있으며, 행동 키와 콘텐츠 버전 등 서버가 결정하는 필드는 서버 함수만 기록할 수 있다.

## 9. 안전과 오류 처리

### 9.1 금지 요청

허위 리뷰, 리뷰 구매, 인위적 저장·트래픽, 검색 순위 조작 요청에는 실행 방법을 제공하지 않는다. 대신 업체 정보 개선, 실제 고객 경험 개선, 합법적인 광고 측정처럼 정상적인 대안을 한 가지 제안한다.

### 9.2 정보 부족

정확한 고객 수, 광고 유입, 재방문 수치를 모르는 것을 오류로 취급하지 않는다. 해당 지표를 추정해 단정하지 않고, 추천을 바꿀 만큼 중요한 경우에만 측정 행동을 제안한다.

### 9.3 AI 장애

- 질문 분류 실패: 선택한 고민 카드 또는 `unknown` 규칙으로 처리
- 답변 생성 실패: 선택된 행동의 템플릿 답변 표시
- 응답 지연: 진행 상태를 표시하고 재시도를 제공하되 사용자 질문을 중복 저장하지 않음
- 스키마 오류: 잘못된 응답은 사용자에게 노출하지 않고 기본 답변으로 대체

AI를 사용할 수 없는 상황에서도 고민 카드 기반 코칭은 완료할 수 있어야 한다.

## 10. 사용자 평가

각 답변 아래에 다음 세 가지 평가를 제공한다.

- 도움이 됐어요.
- 너무 어려워요.
- 내 상황과 달라요.

평가는 코칭 콘텐츠 개선에 사용하지만 AI가 스스로 행동 규칙이나 지식 등급을 변경하게 하지 않는다. 운영자가 반복적으로 낮은 평가를 받은 행동과 질문 분류 사례를 검토한다.

## 11. 테스트 전략

### 11.1 규칙 테스트

- 같은 입력에 같은 행동이 선택되는지 확인
- 수용 여력이 없는 매장에 광고 확대 행동이 선택되지 않는지 확인
- 고객 동의가 없을 때 재방문 메시지 행동이 차단되는지 확인
- 데이터가 부족할 때 측정 행동이 선택되는지 확인
- 공식 지식의 검토 기한이 지나면 해당 행동이 제외되는지 확인

### 11.2 분류 테스트

- 같은 고민을 구어체, 오타, 짧은 문장으로 표현해도 적절한 영역으로 분류되는지 확인
- 두 가지 고민이 섞인 질문에서 사용자가 원하는 결과를 우선하는지 확인
- 신뢰도가 낮은 질문을 억지로 특정 영역에 넣지 않는지 확인

### 11.3 안전 테스트

- 허위 리뷰, 트래픽 구매, 순위 보장 요청이 차단되는지 확인
- AI가 승인되지 않은 행동이나 계산을 추가하지 못하는지 확인
- 이름·이메일·연락처가 AI 입력과 분석 이벤트에 포함되지 않는지 확인

### 11.4 사용자 흐름 테스트

- 진단 미완료 사용자가 코치에 진입할 수 없는지 확인
- 후속 질문이 최대 두 개를 넘지 않는지 확인
- 모바일에서 답변 카드와 행동 버튼이 읽기 쉽고 조작 가능한지 확인
- AI 장애 시 템플릿 답변으로 흐름을 완료하는지 확인

## 12. 범위 제외

첫 구현에는 다음을 포함하지 않는다.

- 외부 전자책 원문 검색과 인용
- 제한 없는 범용 AI 채팅
- AI가 스스로 지식과 규칙을 수정하는 기능
- 네이버·POS·광고 플랫폼 자동 데이터 연동
- 순위 추적과 순위 보장
- 원가·세무·노무에 대한 전문 자문
- 코칭 콘텐츠 관리용 별도 관리자 화면

## 13. 완료 기준

- 기본 진단 완료 사용자가 고민 카드 또는 자유 질문으로 코칭을 시작할 수 있다.
- 필요한 경우에만 최대 두 개의 추가 질문이 표시된다.
- 모든 답변은 승인된 15개 행동 또는 명시된 측정·거절 행동 중 하나를 사용한다.
- 답변에 사용자 진단 수치가 정확하게 반영되고 출처 없는 수치를 만들지 않는다.
- 금지된 플랫폼 조작 요청이 차단된다.
- AI 장애 시에도 카드 선택형 코칭을 완료할 수 있다.
- 사용자가 답변을 세 가지 반응 중 하나로 평가할 수 있다.
- PC와 모바일에서 기존 장사네비게이션 UI 구조와 접근성 기준을 유지한다.
