# 질문 4 매출 부족분 입력 단순화 설계

## 목표

질문 4에서 일반 사용자가 이해하기 어려운 매출 분배 입력을 제거하고, 월 영업일만으로 목표 달성에 필요한 추가 고객 수를 쉽게 확인할 수 있게 한다.

## 사용자 경험

- 질문 4에는 `월 영업일` 입력만 표시한다.
- `신규 고객 증가`, `재방문 증가`, `객단가 상승`으로 부족 매출을 직접 나누는 선택 영역은 표시하지 않는다.
- 목표 매출과 현재 매출의 차이는 모두 신규 고객이 채운다는 보수적인 기준으로 자동 계산한다.
- 계산 안내는 다음 의미가 분명하게 드러나도록 쉬운 문장으로 제공한다.
  - 목표까지 하루에 필요한 추가 고객 수
  - 재방문 고객 수를 알기 어려워 모두 신규 고객으로 가정했다는 계산 기준

## 계산 및 데이터 처리

- 매출 부족분, 월 추가 고객 수, 일 추가 고객 수 계산식은 변경하지 않는다.
- 화면에서 분배 입력을 받지 않으므로 새 진단의 `allocation`은 빈 객체로 정규화한다.
- 빈 분배값은 기존 동작대로 전체 부족 매출을 신규 고객으로 환산한다.
- 과거에 분배값이 저장된 진단을 불러올 수 있도록 도메인 타입, 저장 계약, DB 구조와 결과 호환 로직은 유지한다.
- 과거 분배값이 있는 결과 화면은 기존 기록을 그대로 표현할 수 있다.

## 오류 처리

- 제거된 세 입력 필드에 대한 화면 검증과 포커스 이동은 새 진단 흐름에서 실행하지 않는다.
- 월 영업일의 필수값, 숫자 형식, 최소값 검증은 그대로 유지한다.
- 저장되거나 불러온 과거 분배 데이터의 서버 측 무결성 검증은 유지한다.

## 반응형 및 접근성

- 질문 카드의 기존 반응형 레이아웃을 유지한다.
- 제거된 상세 영역만큼 카드 높이가 줄어들어 모바일에서 질문 하나에 더 집중할 수 있게 한다.
- 계산 기준 안내는 작은 주석이 아니라 본문에서 읽을 수 있는 보조 문장으로 제공한다.

## 테스트

- 질문 4에 월 영업일 입력이 표시되는지 확인한다.
- 제거 대상 상세 영역과 세 입력 필드가 렌더링되지 않는지 확인한다.
- 분배값 없이도 전체 부족 매출 기준의 추가 고객 수가 계산되는지 확인한다.
- 질문 4의 월 영업일 검증과 단계 이동이 정상인지 확인한다.
- 과거 분배 데이터의 저장·조회·결과 호환 테스트는 유지한다.
- 전체 자동화 테스트와 프로덕션 빌드를 실행한다.
