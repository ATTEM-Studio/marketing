# 장사네비게이션 비밀 관리자 대시보드 설계

## 목적

운영자가 일반 사용자 화면을 방해하지 않는 숨은 진입 동작으로 관리자 화면을 열고, 가입 현황과 회원별 진단 데이터를 안전하게 확인할 수 있게 한다.

숨은 동작은 관리자 화면의 존재를 덜 드러내는 장치일 뿐 인증 수단으로 간주하지 않는다. 모든 회원 데이터 조회는 서버에서 관리자 세션을 검증한 뒤에만 허용한다.

## 범위

이번 단계에 포함한다.

- 상단 `N` 로고를 5초 안에 10번 누르는 비밀 진입 동작
- 서버에서 검증하는 공용 관리자 비밀번호
- 관리자 로그인 실패 제한, 세션 만료, 로그아웃
- 전체·오늘·최근 7일·최근 30일 가입자 수
- 날짜별 가입 추이
- 회원 검색, 최신 가입순 목록, 중복 의심 필터
- 회원 기본 정보와 최근 진단 상세 패널
- 동일 이메일 또는 동일 지역·상호명 기반 중복 표시
- 모바일과 PC에 대응하는 관리자 화면

이번 단계에서는 제외한다.

- 회원 수정, 삭제, 강제 로그아웃
- 중복 계정 자동 병합
- CSV 다운로드
- 관리자 여러 명의 개별 권한과 감사 로그
- AI 대화 원문 열람

## 비밀 진입 경험

일반 화면의 상단 `N` 로고에 포인터·터치 입력을 기록한다. 5초 안에 10회 입력되면 관리자 비밀번호 모달을 연다. 제한 시간이 지나거나 다른 페이지로 이동하면 횟수를 초기화한다.

키보드 사용자도 로고에 포커스한 뒤 Enter 또는 Space를 같은 방식으로 입력할 수 있다. 진입 동작은 화면에 안내하지 않는다.

로그인 성공 후에는 관리자 화면으로 전환한다. 이미 유효한 관리자 세션이 있으면 비밀번호를 다시 묻지 않는다. 관리자 화면을 새로고침하거나 직접 열더라도 서버 세션이 없으면 회원 데이터는 반환되지 않는다.

## 관리자 인증과 세션

### 서버 전용 비밀

Vercel 환경변수 두 개를 사용한다.

- `ADMIN_DASHBOARD_PASSWORD`: 운영자가 입력하는 공용 관리자 비밀번호
- `ADMIN_SESSION_SECRET`: 관리자 세션을 서명하는 별도의 충분히 긴 무작위 값

두 값은 `VITE_` 접두사를 사용하지 않으며 브라우저 번들, 로그, 오류 메시지 또는 API 응답에 포함하지 않는다.

### 로그인

브라우저가 비밀번호를 HTTPS `POST` 요청으로 보낸다. 서버는 길이 상한을 적용하고 일정 시간 비교를 사용한다. 성공하면 사용자 개인정보가 들어 있지 않은 서명 토큰을 `HttpOnly`, `Secure`, `SameSite=Strict` 쿠키로 발급한다.

세션 유효기간은 2시간이다. 로그아웃하면 쿠키를 즉시 만료시킨다. 비밀번호 또는 세션 비밀이 바뀌면 기존 세션은 더 이상 유효하지 않다.

### 실패 제한

원본 IP를 저장하지 않고 서버 비밀로 해시한 식별자와 실패 시각만 Supabase에 저장한다. 15분 동안 5회 실패하면 추가 시도를 차단한다. 성공 시 해당 실패 기록을 지운다. 관련 테이블과 함수는 `service_role`만 접근할 수 있고 기존 사용자 RLS 권한은 확장하지 않는다.

응답은 비밀번호 오류와 차단 상태에서 관리자 비밀의 존재 여부를 노출하지 않도록 일반화한다.

## 관리자 API 경계

브라우저가 Supabase의 높은 권한 키를 직접 사용하지 않는다. Vercel 서버 API가 매 요청에서 관리자 쿠키를 검증하고, 검증된 요청에 한해서만 서버 전용 Supabase 클라이언트로 데이터를 조회한다.

API는 다음 책임으로 나눈다.

- 로그인, 세션 확인, 로그아웃
- 가입 요약과 날짜별 추이 조회
- 검색·필터·페이지가 적용된 회원 목록 조회
- 특정 회원의 상세 진단 조회

모든 응답은 `Cache-Control: no-store`를 사용한다. 회원 ID는 UUID 형식을 검증하며 목록은 한 번에 제한된 개수만 반환한다. 서버 로그에는 이메일, 이름, 상호명, 설문 응답 또는 비밀번호를 남기지 않는다.

## 대시보드 정보 구조

### 상단 요약

- 전체 가입 회원
- 오늘 가입
- 최근 7일 가입
- 최근 30일 가입
- 최근 30일의 일별 가입 추이

날짜 경계와 표시는 한국 시간 기준으로 계산한다.

### 회원 목록

기본 정렬은 최신 가입순이다. 각 행 또는 모바일 카드에 다음을 표시한다.

- 이름
- 지역
- 상호명
- 이메일
- 가입 날짜와 시간
- 중복 가능성 배지

이름·지역·상호명·이메일 통합 검색, `전체`, `중복 가능성 높음`, `확인 필요` 필터와 페이지 이동을 제공한다. 검색어는 길이를 제한하고 서버 쿼리의 값으로만 전달한다.

### 회원 상세 패널

PC에서는 오른쪽 서랍형 패널, 모바일에서는 전체 화면에 가까운 하단 시트로 표시한다. 다음 블록을 사용한다.

1. 기본 정보
   - 이름, 이메일, 지역, 상호명, 가입일, 마케팅 수신 동의
2. 최근 진단 요약
   - 진단일, 최근 월평균 매출, 목표 월매출, 평균 객단가, 월 영업일
   - 월 고객 수 입력 상태, 월 고객 수, 필요한 추가 고객 수와 하루 목표
3. 고객과 운영
   - 가장 큰 고민, 재방문 데이터 파악 상태, 동의 고객 DB 여부, 메뉴 변경 가능 여부
4. 광고
   - 광고 진행 여부와 사용자가 입력한 노출·클릭·방문·객단가·재방문 비교값
5. 요식업 선택 정보
   - 좌석 수, 하루 홀 운영 시간, 혼잡도, 평균 일행 수, 평균 체류 시간
   - 매장 식사·포장·배달 비중
6. 계산 결과와 추천
   - 부족 매출, 신규 고객 목표, 저장된 진단과 추천 행동

값이 없는 선택 항목은 `입력하지 않음`으로 표시한다. 내부 JSON 키를 그대로 노출하지 않고 대표님이 이해할 수 있는 한국어 라벨과 단위를 사용한다. 가장 최근의 정상 완료 진단을 기본으로 표시하고 과거 진단 개수와 날짜도 함께 보여준다.

AI 대화 원문은 민감한 자유 입력이 포함될 수 있으므로 표시하지 않는다. 이번 단계에서는 AI 코칭 이용 여부, 이용 횟수, 최근 이용일만 표시한다.

## 중복 판정

중복 계정을 자동 삭제하거나 병합하지 않고 검토 배지만 제공한다.

- `중복 가능성 높음`: 공백 제거와 소문자 변환 후 이메일이 동일한 활성 프로필이 2개 이상
- `확인 필요`: 이메일은 다르지만 지역과 상호명을 정규화한 값이 모두 동일한 활성 프로필이 2개 이상

정규화는 유니코드 호환 정규화, 앞뒤 공백 제거, 연속 공백 축소, 영문 소문자화를 적용한다. 이름만 같은 경우는 중복으로 판정하지 않는다. 한 회원이 두 조건을 모두 충족하면 더 높은 단계만 표시한다.

상세 패널에는 같은 중복 그룹에 속한 다른 계정의 기본 정보와 가입일을 보여주되 별도의 삭제·병합 동작은 제공하지 않는다.

## 데이터와 기존 보안 규칙

기존 `profiles`, `stores`, `assessments`, `goals`, `action_plans`, `check_ins`, `coaching_sessions` 데이터를 읽는다. 기존 회원 본인 전용 RLS 정책은 변경하지 않는다.

현재 구조는 인증 사용자 ID를 회원의 실제 접근 기준으로 삼고 제출 이메일은 검증된 로그인 식별자로 사용하지 않는다. 따라서 동일 이메일 회원을 데이터 오류로 단정하지 않고 `중복 가능성 높음`으로만 표시한다.

관리자 로그인 실패 기록 외에 회원 데이터를 복제하는 새 테이블은 만들지 않는다. 집계와 상세 데이터는 원본 테이블에서 서버 전용으로 읽는다.

## 반응형·접근성

- PC: 요약 카드, 가입 추이, 목록과 상세 서랍을 한 화면 흐름으로 구성
- 모바일: 요약 카드를 가로 스크롤 없이 2열로 배치하고 목록을 카드로 전환
- 표 헤더와 버튼에 명확한 접근성 이름 제공
- 모달과 상세 패널을 열면 포커스를 내부로 이동하고 닫으면 원래 위치로 복귀
- 로딩, 빈 결과, 오류, 세션 만료 상태를 각각 명확히 표시
- 회원 목록과 상세 패널에서는 한국어 단어가 어색하게 잘리지 않도록 기존 줄바꿈 원칙 유지

## 오류 처리

- 잘못된 비밀번호: 구체적인 서버 상태를 노출하지 않는 안내
- 반복 실패: 남은 시간을 추측하게 하지 않고 잠시 후 재시도 안내
- 세션 만료: 회원 데이터를 지우고 비밀번호 화면으로 복귀
- 목록 실패: 기존 화면을 빈 데이터로 오인하지 않도록 다시 시도 제공
- 상세 실패: 목록은 유지하고 상세 패널 안에서만 다시 시도
- 부분 데이터: 없는 블록을 숨기지 않고 `입력하지 않음`으로 구분

## 검증 기준

- 5초 안의 로고 10회 입력에서만 관리자 로그인 창이 열린다.
- 관리자 쿠키 없이 모든 관리자 데이터 API가 `401`을 반환한다.
- 잘못된 비밀번호와 반복 시도가 제한된다.
- 관리자 비밀번호, 세션 비밀, Supabase 서비스 키가 빌드 결과와 로그에 없다.
- 가입자 집계가 한국 시간 기준 날짜와 일치한다.
- 검색, 페이지 이동, 중복 필터가 서버 데이터와 일치한다.
- 회원 상세가 저장된 최신 완료 진단을 한국어 라벨과 단위로 표시한다.
- 동일 이메일과 동일 지역·상호명 중복 단계가 구분된다.
- 일반 회원은 기존 RLS를 통해 다른 회원 정보를 읽을 수 없다.
- 모바일과 PC에서 모달, 목록, 상세 패널을 키보드와 터치로 사용할 수 있다.
- 전체 자동 검증, 보안 검사, 프로덕션 빌드와 실제 배포 화면 검증이 통과한다.
